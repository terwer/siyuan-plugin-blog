## 关键问题
1. 手机端目标左右边距已确认：尽量紧凑，原则上 4px 以下。
2. “手机端”适配范围暂按常见手机宽度（约 320–430px）验证；如运行时发现小平板/折叠屏同源问题，再单独记录。
3. 本次优先修复分享页 `/s/...` 的阅读体验；如同类公开阅读页复用同一容器且同源受影响，可随真实样式链路一起覆盖。

## 已做决策
| 决策 | 理由 |
|------|------|
| 先建立文件规划，不立即修复 | 用户明确表示“不着急马上修复”，希望使用 plan with files |
| 后续优先检查运行时页面实际样式 | 该问题是渲染体验缺陷，运行时行为比源码推测更可靠 |
| 实现前确认模糊设计决策 | 项目要求不确定的技术细节、业务逻辑、设计决策必须主动确认 |
| 移动端左右边距按 4px 以下目标处理 | 用户已明确要求“紧凑，原则上 4px 以下，立即开始修复” |
| 移动端断点采用 `max-width: 768px` | 覆盖常见手机与窄屏阅读场景，桌面端保持原有布局 |
| ~~右侧/左侧功能按钮移动到底部浮动~~ | 已撤销：用户反馈该结构性改动破坏文档树、大纲、AI 助手，不能作为方案 |
| 后续禁止改动侧栏/AI 的结构和按钮布局，除非先证明不破坏功能 | 用户明确要求禁止丧失任何功能 |
